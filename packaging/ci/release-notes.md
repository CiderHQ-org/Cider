Quadra 0.36.p1 fixes the camera that kept turning after the right mouse button was released when the left button had been clicked during a right-button drag.

- **Right-button camera drag:** Darling's window keeps one mouse-down location for every button and invalidates it when any button goes up. After a left click during a right-button drag, the right button's drags and its release no longer reached the game, so it kept the mouse lock and the camera followed the mouse until the menu was opened. The window event hook now keeps the location while the other button is held. This applies to X11 and native Wayland.

Validation: a new AppKit regression in a disposable Darling prefix with the built shim sends right-down, left click and right-up (and the reverse order) to a recording view. Before the change the view received right-down, left-down and left-up only; it now receives every event, and a stray drag with all buttons up is still dropped. Older raw-mouse and pointer-fallback assertions in the same fixture already failed before this change and still do. The fix has not yet been confirmed in a game session.

The new GTX 1060 / Wayland / Zink / MangoHud exit and the RX 6800 loading crash remain undiagnosed: neither supplied log includes a fatal fault address or stack. The Renoir/Metal memory mitigation still needs gameplay confirmation on the affected laptop. This patch does not claim to fix those crashes.

Fully close and reopen Quadra after updating. OpenGL remains the default; VR requires OpenGL or Vulkan/Zink. Native packages include the matching Metal host and framework. Flatpak does not include the Metal bridge yet. Install `.pkg.tar.zst` on Arch derivatives, `.deb` on Ubuntu 24.04+/Debian 13+, or the binary `.rpm` on current Fedora. Darling/CiderDarling downloads remain separate. Source archives, build recipes and `SHA256SUMS` are attached.
