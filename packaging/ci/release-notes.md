Quadra 0.37.p3 fixes the middle and extra mouse buttons and the keys outside the main block, which did nothing or the wrong thing in game. Nothing else changes from 0.37.p2.

- **Middle click and side buttons:** Darling's window code has no case for them, so every press, drag and release was dropped before Roblox saw it, on X11 and on native Wayland. They now reach Roblox the way the left and right buttons do.
- **Keys outside the main block:** on X11, Insert, Right Alt/AltGr, Menu, F13 to F20, keypad = and the < > | key beside Left Shift reached Roblox as the A key, because Darling's key table stops at an Apple keyboard. They now arrive as the keys a Mac sends for them (Insert as Help). On native Wayland the same keys were dropped and are now sent. Media keys and F21 and above still have no Apple equivalent.
- Everything in the 0.37, 0.37.p1 and 0.37.p2 notes still applies: Roblox Studio in its own section, the move to QuadraHQ/Quadra, the Simplified Chinese translation, Studio's Vulkan layer in the distro packages and the Grid look fixes.

Validation: in Darling's real window code under Xvfb, a middle press, drag and release reached the game's view and Insert, Right Alt, the ISO key, Menu and F17 arrived with the right key codes; with 0.37.p2's shim the same test received no middle events and Insert as key 0. The 432 unit tests and the native tests, including new ones for the key tables, pass. It was not tried in a live Roblox game, so how Roblox itself reads Help, Menu and the extra buttons is unchecked.

Fully close and reopen Quadra after updating. Studio is not in the Flatpak. OpenGL remains the default for the game; VR requires OpenGL or Vulkan/Zink. Native packages include the matching Metal host and framework. Install `.pkg.tar.zst` on Arch derivatives, `.deb` on Ubuntu 24.04+/Debian 13+, or the binary `.rpm` on current Fedora. Darling/CiderDarling downloads remain separate. Source archives, build recipes and `SHA256SUMS` are attached.
